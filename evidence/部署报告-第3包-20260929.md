## 5. 与文档不一致的地方（以实测为准，均已写进回执）

1. **host 占用口径（影响最大）**：文档称 host ≈5.5 GB、`cpu_bytes` 是“上限不是预占”。实测默认 `KVMEM_CPU_GB=12` 时引擎**私有 19.59 GB / 工作集 18.34 GB**，31.6 GB 机器只剩 **2.0 GB** 可用内存；arena 随 `KVMEM_CPU_GB` **线性预占**（12 GiB→5461 槽，4 GiB→1820 槽）。
   **处置**：按 03 页旋钮改 `KVMEM_CPU_GB=4` ⇒ 私有 10.84 GB、可用 11.42 GB，**性能无回退**。
2. `agent\governance.json` 与 `agent\must-do.json` 的 id **不是一一对应**（前者含 C6/B2b/B5/E1/E2/A1/A2/A3/F1/D4–D7 等本档不存在的条目，且夹带 ninfer 线文案）。
3. **src-tree 清单滞后 1 件**：`scripts/snapdragon/windows/setup-build.ps1`（清单 `f39347d0…` vs 实测 `47E48CE9…`；它是全树 3605 件中唯一晚于清单生成时间的文件）＋ 3 行零哈希占位行（`[id]`/`[[section]]` 路径）。**不是丢件**（文件数 3605=3605，其余 3602 条全对）。
4. ⚠️ **`KV_DTYPE=int8` / `bf16` 是非法值 —— 照 03 页抄会直接起不来**：引擎原文 `unsupported cache type (want f16|f32|q8_0|q5_0|q4_0)`，`errorlevel=1`、端口无监听；排错篇 17 条症状里也没有这一条。本档合法值只有 `f16|f32|q8_0|q5_0|q4_0`（`int8` 的最近等价是 `q8_0`，实测质量无改善、显存 +320 MiB、arena 槽减半）。
5. **`-c` 不吃 host，`--kvmem-cpu-gb` 才吃**：ctx 65536/131072/262144 三档在 `cpu-gb=4` 下 host 私有内存**恒为 11.06 GB**；且引擎**不检查 arena 容量 ≥ ctx**（1820 槽 = 232,960 token < ctx 262,144 也照常启动）⇒ 想开 262144 应把 `KVMEM_CPU_GB` 提到 ≥6（2730 槽 = 349,440 token）。
6. `KVMEM_GPU_R` 是**上限不是预占**：0.5 与 0.25 的显存峰值完全相同（6349 MiB），与表格“显存涨”的表述不符；“不爆的上限”出现在 `budget=ctx(65536)+ratio 0.5`（峰值 7371 MiB，余量仅 ~0.8 GB，且无任何收益）。
7. “retrieval 每请求 +1.9~3.5 s”：只换 method 时确实 −2.0%（29.5k 提示），但按处方整体改用 `start-retrieval.bat` 后**更快**（工作集同时抬到 16384/0.25）。
8. `自检-引擎与卡匹配.ps1` 的 [4] 结论是 ninfer 线文案（指向不存在的 `infer-serve.exe`），建议按档分支。

## 6. 补丁包（pkg5）为何**没有**打

`pkg5` 只补两件事：**A3 调度（token→`grid.y`）** 与 **自编引擎 `0xC0000135` 处方**，两者都是 **ninfer 线**。三处明文排除本档：

- `pkg5\README.md` §5：**“省显档（llama+KVMem）不适用：那一档不是 ninfer 引擎，没有这个内核。”**
- `pkg5\docs\02-实测回执…md` §6：**“❌ 但省显档不适用（不是 ninfer 引擎）”**
- `pkg5\sched3-patch\README-怎么用.md` §2：**“超低显存档 走 llama.cpp 线，本补丁对它不适用（它的 src-tree 是 llama-kvmem）”**

