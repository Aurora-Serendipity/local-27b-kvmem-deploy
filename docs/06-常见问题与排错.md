# 06 · 常见问题与排错

## 一、12 个已知坑（全部是本机实测撞出来的，上游文档里没有）

**坑 1 · 长回答之后问大文件，深段检索会失灵** ★最容易踩
现象：先让它写一大段（如 6400 token），紧接着问一个 5 万+ token 的文件，它会答"文件里没有这个函数"——其实**是没取到，不是文件的问题**。
实测：基线和质量档都会中；`budget 32768` 在 **5.3 万**材料上能挡住，**14.5 万挡不住**。
处置：**大文件放在会话的第一个请求**；换文件前**重启引擎**（停机 → 启动，几秒）。

**坑 2 · `KVMEM_CPU_GB` 是"预占"不是"上限"**
文档说 host 占用约 5.5 GB；实测默认 12 GiB 时引擎私有内存 **19.6 GB**，31.6 GB 机器只剩 **2 GB** 可用。
处置：**永远显式设 4 或 6**（启动脚本已经帮你设了）。

**坑 3 · `KV_DTYPE=int8/bf16` 会让引擎起不来**
上游文档让你调 int8/bf16，但本档引擎只认 `f16|f32|q8_0|q5_0|q4_0`，照抄会看到 `unsupported cache type`。
处置：保持 `q4_0`。

**坑 4 · 同一端口能被两台引擎同时绑定**
实测第一台占着 18200，第二台照样打印 `listening on …18200` 并常驻（Windows 地址复用）。**你不会看到"端口被占用"报错**，风险是请求落到哪台不确定。
处置：启动脚本已内置拦截；换配置先停机。

**坑 5 · `--restart` 不存在**
上游排错篇让你用它强制重启；实测本 build 没这个开关（`unknown flag: --restart`）。
处置：要重启就**停机再启动**。

**坑 6 · `sink = budget` 时长提示每个请求都 500**
实测 `sink=budget=8192` + 长提示 → 两次都 HTTP 500，日志 `prepare_working_set: incoming block 90 was not placed on GPU`；**而 17 token 的短请求仍返回 200**（所以别用短请求验证这个）。
处置：`sink` 必须显著小于 `budget`（本方案 4096 vs 32768）；启动件有硬守卫（违规 exit 21/22）。

**坑 7 · 输出被"悄悄截断"**
超过 `KVMEM_GEN` 就停，响应里 `finish_reason=length`，**不报错**。
处置：看到 `length` 就是被截断——让它"接着写"，或分两次问。

**坑 8 · 短提示的引擎读数极度不准**
17 token 提示能测出 **26 t/s** 的 prefill（真实值 ~290）。
处置：判断快慢**必须**用长提示 + 长输出（见 [docs/03](03-调优方法与实测口径.md) 的 C1 口径）。

**坑 9 · 路径必须纯 ASCII**
交付包路径含中文会让引擎报"系统找不到指定的路径"（空格没问题）。
处置：放在纯 ASCII 路径下（例如 `D:\Local Model\...`）。

**坑 10 · 别改 `engine\` 里的任何文件**
那是冻结件，sha256 与清单一致（`自检-搬家.ps1` 会验）。要换版本请另存并记录 sha256。

**坑 11 · 清了浏览器数据，对话历史会一起没**
历史存在浏览器本地存储里：清"网站数据/缓存"、无痕窗口、换浏览器（Chrome ↔ Edge 各存各的）都会看不到历史。
处置：用「备份到文件夹」绑定一个目录（每轮自动落盘），或定期「导出全部」。

**坑 12 · 同一会话开两个标签页同时改**
两边都能改，**以最后写入的那次为准**（后写覆盖先写）。页面之间会自动同步**列表**，但同一会话的并发编辑无法合并。
处置：一个会话只在一个标签页里编辑。

| 症状                                        | 原因                                       | 处置                                                     |
| ------------------------------------------- | ------------------------------------------ | -------------------------------------------------------- |
| 双击启动脚本，提示"已经有引擎在监听"        | 上一次没停干净                             | 先双击停机脚本，再启动                                   |
| 启动脚本报"在超时时间内没有等到 200"        | 内存不足 / 端口被别的程序占 / 包被移动     | 看引擎窗口最后几行；关掉吃内存的程序；跑 `状态检查.cmd`  |
| 引擎窗口一闪就没                            | 缺运行库 / 路径含中文                      | 确认 `engine\` 里 3 个 CUDA dll 在；确认路径纯 ASCII     |
| 每个请求都 500                              | sink/budget 被改坏                         | 用启动脚本（它设好了 4096 / 32768）                      |
| 回答说到一半没了，`finish_reason=length`    | 撞了 8192 输出上限                         | 让它"接着写"，或要求简短                                 |
| 回答乱码/胡言乱语                           | 权重或引擎损坏                             | 跑交付包自检 / 核对 sha256                               |
| 问大文件答"文件里没有"                      | 坑 1（会话污染）                           | 重启引擎，把大文件放第一问                               |
| 机器变卡、风扇狂转                          | 长上下文档灌满时占 ~19 GB 内存             | 关掉别的程序；或改用日常档                               |
| 停机后显存没回落                            | 有孤儿进程                                 | 停机脚本会按精确路径清理孤儿；再不行重启机器             |
| `聊天.html` 发出去报"出错了"                | 引擎没在跑 / 端口不是 18200                | 双击启动脚本，看到 `[就绪]` 再用；跑 `状态检查.cmd`      |
| 浏览器地址栏直接开 `127.0.0.1:18200` 是 404 | 本方案不含引擎自带 Web UI 资源（正常现象） | 用 `聊天.html`，别开那个地址                             |
| 聊天页在个别浏览器发不出请求                | 部分浏览器会拦 `file://` 页面访问本机端口  | 换 Chrome / Edge 打开；或用 curl / Python SDK            |
| 想换端口                                    | 端口被占                                   | 设 `KV_PORT`；⚠️ 记得同步改 `聊天.html` 里写死的两行地址 |

## 三、FAQ

**Q：要联网吗？会花钱吗？内容会上传吗？**
不要联网；不花钱（电费之外）；内容不出本机。

**Q：关掉聊天页会怎样？**
没事。只有关掉那个**黑窗口（引擎）**模型才停。

**Q：能同时问好几个问题吗？**
不能。单槽服务，一次一个请求，等它答完再发下一句。

**Q：为什么第一次读大文件要等十几分钟？**
冷读要 prefill：25 万 token ≈ 17 分钟（250 t/s）。**同一个前缀的后续提问会命中缓存**（5.3 万材料的实测是 193.9 秒 → 4.9 秒），所以"先喂一次、再多轮追问"。

**Q：为什么它写一半就停了？**
两种可能：① 撞 8192 输出上限（看 `finish_reason=length`）；② 模型自己觉得写完了（`stop`）。前者让它"接着写"。

**Q：怎么让它"先想再答"？**
聊天页勾选「先推理再答（思考）」并选强度。注意**思考量计入 8192 输出上限**。

**Q：历史会丢吗？**
不会（自动存在浏览器本地）。但**清浏览器数据会**——所以绑「备份到文件夹」或定期导出。

**Q：聊太长了怎么办？**
底部有 token 计量条。**永久解法**是「压缩上下文」（模型写摘要 + 原文存档可还原）；**临时解法**是勾「只带最近 N 轮」（只影响本次发送，历史不动）。

**Q：能换成别的模型吗？**
可以，但**必须重新做全套量测**：显存/内存账、`budget` 临界点、`ctx` 与池容量、以及 17 针质量剖面。**参数不可照搬**（见 [docs/07](07-可复用经验.md)）。

**Q：能同时跑两个不同档吗？**
不能，也不能同时开两台——同一端口能被绑两次且不报错，请求落到哪台不确定。
