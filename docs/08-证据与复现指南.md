## 2. 回执（receipt）里有什么

`回执-receipt-tier1-20260929.json` 是**机器可读**的主证据，schema 为 `receipt/1`，顶层字段：

| 字段                                                             | 内容                                                                 |
| ---------------------------------------------------------------- | -------------------------------------------------------------------- |
| `machine` / `package_path` / `engine_sha256` / `artifact_sha256` | 环境与制品指纹                                                       |
| `sha_verification`                                               | 校验和比对结果                                                       |
| `steps` / `gates`                                                | 部署步骤与通过情况                                                   |
| `numbers`                                                        | 速度/显存/内存基线原始记录                                           |
| `tuning_sweep`                                                   | 13 个旋钮的扫描结果                                                  |
| `verification_round_2` / `_3` / `_4`                             | 历次"确认无遗留"的验证记录（第 4 轮＝全体系一致性审计 + 全功能回归） |
| `code_workload_and_levers`                                       | 代码负载与可用杠杆（思考开关等）                                     |
| `long_answer_long_context_tuning`                                | 长回答/长上下文调优过程                                              |
| `ctx_262144_and_generation_ceiling`                              | 262144 上下文与 8192 输出上限的证明                                  |
| `final_config_verification`                                      | 最终两档配置的验收数据                                               |
| `contradictions`                                                 | **11 条"上游文档这么说、本机实测不是"**                              |
| `skips`                                                          | 明确跳过没做的项（及原因）                                           |
| `verdict`                                                        | 结论                                                                 |

## 3. 怎么自己复现每一条结论

### 3.1 复现"速度"（2 分钟）

```powershell
# 先启动引擎（日常档）
.\launchers\一键启动-日常推荐.cmd

powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\measure-c1.ps1 `
  -Port 18200 -Rounds 4 -Warmup 1 -OutTokens 500 -PromptWords 900 -Tag myrun
```

预期：`prefill : median ≈ 290 t/s`、`decode : median ≈ 27 t/s`，且每轮 `cache_hit=0`。
**若数字明显偏低**：检查是不是有别的程序抢 GPU、或提示被改短了（见 [docs/03](03-调优方法与实测口径.md) 陷阱 1）。

### 3.2 复现"质量 17/17"（约 3 分钟）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\profile-needle.ps1 `
  -Port 18200 -TargetTokens 24000 -MaxTokens 400 `
  -Depths '0.005,0.0669,0.1288,0.1906,0.2525,0.3144,0.3763,0.4381,0.5,0.5619,0.6238,0.6856,0.7475,0.8094,0.8713,0.9331,0.995' `
  -Tag myprofile
```

预期：`-> 17/17`、`missed : (none)`、`out_tokens = 277`、`finish=stop`。
**必看**：若 `out_tokens` 撞到 `-MaxTokens`，脚本会打印"结论无效"——那是**输出截断**，不是检索失败。

### 3.3 复现"25 万 token 上下文 + 8192 长回答"（约 25 分钟）


| ----------------------------- | -------------------------- |
| `t1_prompt_tokens`            | ≈ **252,862**              |

**跑之前确认**：可用内存 ≥ 20 GB（灌满时要 19.2 GB），且没有别的吃内存程序。

## 4. 数字的口径备忘（免得误比）

- 所有 t/s 都来自**引擎自报 timings**，不是客户端掐表；
- 所有对比都是**同口径**（长提示 + 长输出 + 贪心 + 丢首轮 + 中位）；
- `out_tokens` 顶到上限的样本**一律判为无效**（截断会伪装成各种结论）；
- 前缀缓存命中时 prefill 数字**不可比**（必要时用 nonce 排除）；
- 显存数字是**峰值**（`nvidia-smi` 采样），内存数字是**引擎进程私有内存**。

## 5. 已知的"跳过项"（如实记录）

- **视觉/图片**：未验证（8 GB 卡不建议开）。
- **recency 对照臂**：历史结论 12/17，本轮未重跑（只重跑了最终配置的 retrieval 两档）。
- **「备份到文件夹」的原生目录选择框**：无法自动化点击，需真人授权一次；已验证目录里确实产生 `<标题>__<id>.json` 实体文件。
